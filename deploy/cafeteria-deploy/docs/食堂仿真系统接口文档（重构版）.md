# 食堂仿真系统接口文档

**版本**：1.0  
**日期**：2026-06-02  
**范围**：仅定义 A（配置/前端）与 B（仿真引擎）、B 与 C（数据记录）之间的数据契约。

---

## 1. 设计原则

- **A 负责决策**：所有可调参数（权重、窗口数、椅子数）由 A 传入，B 只执行。
- **B 负责仿真**：根据 A 的参数推进状态，每步输出关键指标给 C。
- **C 负责记录**：接收 B 的快照数据，写入文件或数据库。

---

## 2. 接口 A → B：仿真配置

B 启动时，A 必须发送以下 JSON 配置。**所有参数均由前端/A 提供**。

### 2.1 请求体字段

| 字段名              | 类型    | 必填 | 说明                                                         |
| ------------------- | ------- | ---- | ------------------------------------------------------------ |
| `windowCount`       | `int`   | 是   | 食堂打饭窗口数量，≥1                                         |
| `chairCount`        | `int`   | 是   | 食堂椅子总数（座位数），≥0                                   |
| `distanceWeight`    | `float` | 是   | 距离权重（影响学生选择窗口或座位的偏好），取值范围 0.0~1.0   |
| `queueRandomWeight` | `float` | 是   | 排队时随机选择的权重（与距离权重共同决定最终选择），取值范围 0.0~1.0 |
| `seatRandomWeight`  | `float` | 是   | 就座时随机选择的权重（与距离权重共同决定最终选择），取值范围 0.0~1.0 |

**派生规则（B 内部可自行计算，但 A 无需传入桌子数）**：  
桌子数量 = `chairCount / 4`（取整规则由 B 决定，建议向下取整）。A 只需提供椅子总数。

### 2.2 示例

```json
{
  "windowCount": 4,
  "chairCount": 120,
  "distanceWeight": 0.7,
  "queueRandomWeight": 0.3,
  "seatRandomWeight": 0.2
}
```

### 2.3 传输方式

建议 HTTP POST `/api/simulation/init` 或通过启动参数传递。具体协议由实现约定。

---

## 3. 接口 B → C：每步状态数据

每完成一个仿真步（例如 1 秒），B 向 C 推送当前状态快照。

### 3.1 消息体字段

| 字段名         | 类型         | 说明                                            |
| -------------- | ------------ | ----------------------------------------------- |
| `simTime`      | `int`        | 当前仿真时间（秒）                              |
| `freeSeats`    | `int`        | 当前空椅子数量，满足 0 ≤ freeSeats ≤ chairCount |
| `queueLengths` | `array[int]` | 每个窗口的排队人数，数组长度 = windowCount      |
| `enterCount`   | `int`        | 本步新进入食堂并加入队列的人数                  |
| `exitCount`    | `int`        | 本步离开食堂的人数（用餐完毕释放座位）          |

### 3.2 示例

```json
{
  "simTime": 42,
  "freeSeats": 86,
  "queueLengths": [3, 2, 5, 1],
  "enterCount": 4,
  "exitCount": 3
}
```

### 3.3 传输方式

C 可提供回调函数供 B 调用，或 B 通过 HTTP POST 发送到 C 的监听地址（如 `/api/step`）。推荐使用内存回调以降低延迟。

---

## 4. 错误处理与扩展

- 若 A 传入的参数不合法（如 `windowCount ≤ 0`、权重超出 [0,1]），B 应拒绝启动并返回错误信息。
- 未来新增字段需通过版本号协商，本版本为 `v1`。

---

## 5. 完整交互时序

1. **A 启动 B**，发送配置 JSON。
2. **B 初始化**，根据 `chairCount` 计算桌子数等内部状态。
3. **仿真循环**（每步）：
   - B 根据权重规则更新排队和就座。
   - B 向 C 推送 `{simTime, freeSeats, queueLengths, enterCount, exitCount}`。
4. **仿真结束**：B 可发送结束信号（可选）。

---

## 6. 与之前文档的差异

| 项目     | 之前（错误）    | 现在（正确）                      |
| -------- | --------------- | --------------------------------- |
| 权重来源 | 可能 B 内部固定 | **A 必须传入**                    |
| 桌子数量 | 要求 A 计算     | **B 自己根据 chairCount/4 计算**  |
| B→C 数据 | 含历史累计值    | **仅本步快照**（enter/exit 增量） |
